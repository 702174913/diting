## 1. 状态机（`TaskStatus`）

```text
UPLOADED → QUEUED → SUBMITTING → TRANSCRIBING → PARSING → WAITING_ROLE → ANALYZING → COMPLETED
                                                                         ↘ FAILED / INVALID
任意可删状态 → DELETING → DELETED（删除优先，终态不接受回调）
```

- 迁移只允许走白名单（`canTransitionTo`）：**不能跳级完成**（`TRANSCRIBING → COMPLETED` 非法）、
  **终态不能复活**；`COMPLETED → ANALYZING` 是唯一例外，用于版本重算而不是改分。
- `COMPLETED` 有硬性前置：**必须已有已发布报告**——`markCompleted(task, hasPublishedReport)` 在没有
  报告时直接拒绝，杜绝“先完成、后无结果”。报告发布属 S08，本阶段没有发布者时一律拒绝。
- 旧值转换：`PENDING → QUEUED`、`ONGOING → TRANSCRIBING`，由迁移脚本 `V3` 与
  `TaskStatus.fromLegacy` 两处保持一致；**两端同批切换**（小程序的状态判定与文案已改为新枚举）。
- 新登记任务直接进入 `QUEUED`：`UPLOADED` 的语义由上传会话的 `VERIFIED` 承载（S04），
  不重复造一个“已上传”的任务状态。

## 2. 领取：租约 + 版本 CAS

```sql
-- 领取（影响 0 行即放弃本轮）
UPDATE recognition_tasks SET version = version + 1, status = #{next},
       lease_until = #{leaseUntil}, attempt_count = attempt_count + 1
WHERE id = #{id} AND version = #{version} AND deleted_at IS NULL
  AND (lease_until IS NULL OR lease_until < NOW(3));
```

- 到期任务筛选同样带三条件：退避时间已到、租约已过期、未删除；客户端轮询**不触发**任何调度。
- 领取只有两种形态：**同状态续租**（中间态再领一次）或**合法迁移**（`QUEUED → SUBMITTING`），
  其它一律放弃——这条规则在首轮测试里挡住了我最初把“续租”写成非法迁移的 bug。
- 进程中断恢复不需要额外机制：租约过期即可被重新领取（JOB-04 已验）。

## 3. 提交与对账（不盲重提）

| 情形 | 处理 | 额度 |
|---|---|---|
| CreateTask 正常返回 | 登记远端任务号 → `TRANSCRIBING` | 转**已消费**（CAS 幂等） |
| 确定性失败（如未配置、参数被拒） | 退回 `SUBMITTING` 退避重试，记 `SUBMIT_FAILED` | 保持**预占** |
| 不确定失败（超时/网络） | 记 `SUBMIT_UNCERTAIN`，进入对账 | 保持**预占**，既不退还也不重提 |
| 对账次数达到上限（默认 5） | 标记 `FAILED` + `SUBMIT_UNRECONCILED`，停止重试 | 保持**预占**，等待人工对账 |
| 远端明确失败 | `FAILED` + `REMOTE_FAILED` | **不退额度**（云端已受理，不是“未受理”） |
| 结果地址失效/结构异常 | 停在 `PARSING` + `PARSE_FAILED`，可重试 | 不变 |
| 空音频 | `INVALID` | 不变 |

远端幂等能力未核实前**不做自动重提**：这条是开发文档 §5.3 的硬要求，也是本阶段最重要的行为约束。

## 4. 解析落库与角色等待

- `PARSING` 阶段下载并解析结果，**先清旧句再按时间序插入**（`uk(task_id, sequence)`），
  重跑解析不会出现半新半旧；重跑**不会**再次提交付费转写（JOB-09）。
- 解析结果是空音频时判 `INVALID`，不写任何句子。
- 落库后停在 `WAITING_ROLE`：角色确认（S08）与规则分析（S07）在后续阶段接上；
  测试覆盖「没有已发布报告不能置完成」的守卫。

## 5. 回调与墓碑

- 回调**只唤醒**：按 `Data.TaskId` 找到关联任务后清掉退避时间，状态由服务端主动查询判定；
  回调携带的结果地址**不被采用**（防 SSRF 与伪造结果）。
- 重复、乱序、未知任务号、已删除任务的回调都返回 200 且不改变状态（幂等，不泄露内部状态）。
- 墓碑优先：`deleted_at` 非空的任务不领取、不发布、不被回调复活。
