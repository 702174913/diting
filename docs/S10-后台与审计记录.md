## 2. 脱敏（OPERATOR 视角）

- 掩码**逐字符替换且与原串等长**（手机号保留前 3 后 4、身份证保留前 4 后 4、邮箱保留首字符与域名），
  因此 `ranges` 全部仍然有效——这是开发文档里明确点出的「脱敏后偏移错位」风险的对策。
- 只对高置信模式脱敏：手机号、身份证、银行卡、邮箱、工号。
  **姓名不做猜测式脱敏**：没有名单就猜名字会把普通词汇也涂掉，反而降低可用性；
  上线前需要业务给出名单来源（列入待确认项）。
- 响应里带 `redacted: true`，方便前端提示「当前为脱敏视图」。

## 3. 原件签发

- 仅 ADMIN；服务端检查「未删除、未清理、未过保留期」，任一不满足返回 404 `AUDIO_EXPIRED`。
- 签发**必留痕**（`AUDIO_PRESIGN`），审计里只记「签发事实 + TTL + 是否已清理」，
  **不记链接本身**；留痕只能证明「授权链接已签发」，不等于已经听完。

## 4. 审计纪律

- 动作覆盖：配置保存、规则新增/修改/停用、账号创建/修改、角色确认（C 端与后台）、
  原件签发、单条删除、全部抹除。
- 只写元数据（动作、目标、结果、版本号、角色、启用状态）；E2E 直接查库断言：
  **不含对话原文、不含 `http` 链接、不含密码字段**。
- 查询接口仅 ADMIN，按动作与身份域筛选分页。

## 5. 三个新页（`diting-admin`）

| 页面 | 能力 |
|---|---|
| `views/recordings` | 按用户/状态/日期分页筛选；详情面板展示逐句（含角色与说明）、命中证据；确认角色（触发重算与新版本）、签发原件（仅 ADMIN）、删除（仅 ADMIN，二次确认） |
| `views/rules` | 列表 + 新增/修改表单（类型、角色范围、触发/应答词、窗口、扣分、依据说明）；修改即生成新版本；停用只影响未来集合；只读角色看不到写按钮 |
| `views/settings` | 三项配置 + 版本号；保存带 `expectedVersion`（冲突提示刷新）；**读取失败时禁用保存**，避免用默认值覆盖真实配置 |
| `views/audit` | 保留权限矩阵说明，日志改为**真实审计数据**（时间、身份域、动作、目标、结果），无权限时明确提示而不是显示空表 |

菜单与路由：`layouts/AdminLayout.vue` 在「业务（含个体数据）」加入录音资产，在「治理」加入规则库与策略设置；
沿用原有 UnoCSS 与图标风格，未引入新组件库。

| 层 | 用例 | 结果 |

| 前端 | 三页 + 审计页 + 布局/路由的 SFC 解析与模板编译、`api/admin.ts` 打包 | 通过（无新增依赖） |

**E2E 抓到的真实缺陷（已修）**：录音资产列表把日期参数传成 `null` 时，
`LocalDate.parse(null)` 直接抛 NPE 变成 500 —— 原因是 Java 会先求值条件表达式的参数，
再判断 MyBatis-Plus 的条件开关。已改为分支式构建（缺参数就不加条件），符合「先确认再使用」的写法。

证据文件（`docs/evidence/S10/`）：`java-tests-*.log`、`e2e-admin-*.log`。
复现见 `diting-server/src/test/resources/admin/README.md`。
