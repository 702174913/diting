# S11 PDF 与 ZIP 异步导出 · 记录

版本：v1.0 · 日期：2026-09-24 · 阶段：S11
规格依据：[开发文档](./开发文档.md) §7.2/§7.3 接口、§9 权限与导出；[开发计划](./开发计划.md) §14 S11。

**结论摘要**：导出做成**异步作业**（创建 → 排队 → 生成 → 短时下载），PDF 用固定模板 + 嵌入中文字体，
ZIP 打包该版本 PDF 与**未改动的原始音频**；同 owner + 版本 + 选项复用有效产物，发布前复查墓碑。
验证：**176 项单元/切片测试**（S11 新增 5 项 PDF 渲染）+ **28 项端到端断言**全部通过。

---

## 1. 接口（C 端与后台独立路由、独立身份域）

| 方法/路径 | 说明 |
|---|---|
| `POST /api/report/{id}/exports` | C 端创建：`{reportVersionId, withAudio}` → `{exportId, status, fileType}` |
| `GET /api/exports/{exportId}` | C 端查询：完成时才返回短时 `downloadUrl` 与 `expiresAt` |
| `POST /api/admin/recordings/{id}/exports` | 后台创建（ADMIN/OPERATOR），共用服务、独立身份域 |
| `GET /api/admin/exports/{exportId}` | 后台查询 |

- **GET 只查状态，不触发副作用**：产物由调度器异步生成（`diting.export.tick-interval-ms`）。
- 后台 token 不能调 C 端路由、C 端 token 不能调后台路由（身份域拦截器强制，E2E 验过 403/404）。
- 跨身份域、跨用户的作业读取一律 404，不泄露存在性。

## 2. PDF

- **固定模板**：A4、固定页边距/字号/行高，超页自动分页；内容含记录编号、生成时间、**报告版本**、
  分数与阈值、逐句判读（含角色）、命中与依据（规则名 + 扣分 + 说明）、页脚免责说明。
- **命中处标红**（2026-09-24 补齐）：逐句判读里命中原话按报告版本的 UTF-16 区间用**红色**绘制，
  区间重叠时取并集、越界时退化不越界切片；「命中与依据」每条前加红色圆点。
  版面样式改为显式枚举（TITLE/SECTION/BODY）——**旧实现把 `#TITLE#`/`#SECTION#` 前缀原样画进正文**，
  已修复并有测试锁住（`PdfBoxReportRendererTest#templateMarkersNeverLeak`）。
- **页脚声明**（需求指定文案）：
  「本服务仅记录通话内容，不构成法律意见，/ 不作为处理结果承诺。」+「所引规范条文请以现行有效版本为准。」
- **嵌入字体**：`diting.export.font-path` 指向中文字体（TF），加载后按子集嵌入，避免异地缺字；
  **字体不可用时返回 503 NOT_CONFIGURED，不产出空 PDF**。
- **不拉取任何远端资源**：文本按纯文本绘制，不做 HTML 解析——注入内容原样落盘为文本，
  PDF 结构里不会出现 `/URI`、`/JavaScript`、`/EmbeddedFile`（E2E 直接对字节断言）。
- 长文折行按**字符宽度**计算（中文按实际宽度，不按字节），不会把中文切坏。

## 3. ZIP 与有效期

- ZIP 内含 `report.pdf` 与该版本的**原始音频**（不改动、不转码）；E2E 解压后比对 **md5 与上传时一致**。
- 原件已清理或超过保留期 → 直接拒绝打包（404 `AUDIO_EXPIRED`）；纯文本 PDF 不受影响。
- **含音频 ZIP 的有效期不晚于原件保留截止时间**（取两者较早者），下载链接 TTL 15 分钟。

## 4. 复用、并发与失败

- 同 owner + 报告版本 + `withAudio` 若已有**仍有效**的产物，直接复用，不重复生成（EXPORT-04）。
- 单实例串行生成（`batch-size` 控制每轮数量）+ 产物大小上限，避免一次性打满内存。
- **发布前复查墓碑**：记录已删除时作业标记 `TASK_DELETED`，不发布产物（EXPORT-08）；
  失败作业带 `errorCode`，前端据此提示而不是显示空链接。
- 审计：`EXPORT_CREATE` 与 `EXPORT_DOWNLOAD` 都留痕，**只记签发事实与类型，不记链接**；
  并明确「链接已签发 ≠ 已下载」。

## 5. 小程序交互

- `createExport → waitExport（2s 间隔轮询，超时 60s）→ 按类型分流`：
  **PDF 用 `openDocument` 打开**，**ZIP 走下载/保存分享**（微信不支持用文档方式打开压缩包）。
- 未生成完成前不返回地址，界面提示「正在生成…」，失败时提示重试——不出现假成功的「已导出」。

## 6. 测试与证据

| 层 | 用例 | 结果 |
|---|---|---|
| 单元 | `PdfBoxReportRendererTest`：EXPORT-01 中文可读与长文分页、EXPORT-03 注入内容纯文本且 PDF 无外部资源、EXPORT-06 脱敏后仍是掩码且长度不变、字体缺失 503 | 5 项 |
| 端到端 | 独立库 `diting_s11_test` + 8090 实例：EXPORT-04/05/07/08/09/10 + 作业生命周期 + 审计纪律 | **28 项通过** |
| 前端 | 报告页 SFC 编译 + `api/record.ts` 打包与导出面检查 | 通过（无新增依赖） |

**E2E 抓到的两个真实缺陷（已修）**：

1. **`enabled` 同时挡住了定时器与手动推进**：与 S06 管线踩过的是同一个坑——开关只应控制调度，
   手动调用（测试/运维）不该被拦住。已按 S06 的方式修正。
2. **版本号 ↔ 版本 id 语义混淆**：导出按 `reportVersionId`（行 id）取详情，而报告读取接口的入参是
   **版本号**（1、2、3…），导致导出必然失败（404）。已拆成 `detail(task, versionNo)` 与
   `detailOf(task, ReportVersion)` 两个入口，并把语义写进注释与文档。

证据文件（`docs/evidence/S11/`）：`java-tests-*.log`（176 项）、`e2e-export-*.log`（28 项）。
复现见 `diting-server/src/test/resources/export/README.md`。
