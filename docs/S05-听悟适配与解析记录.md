## 1. 客户端适配修正（对照开发文档 §2 的差距清单）

| 问题 | 处理 |
|---|---|
| 转写参数写在顶层 `Transcription` | 改为 **`Parameters.Transcription`**，`Diarization.DiarizationEnabled` 同层；测试断言 `Parameters` 出现在 `Transcription` 之前且顶层不再有该键 |
| 响应直接在顶层读 `TaskStatus`/`Result` | 统一读 **`Data`** 层：`Data.TaskId`、`Data.TaskStatus`、`Data.Result.Transcription`；`JsonNodeReader` 按点号路径取值 |
| 未完成就去解引用 `Result`（可能 NPE） | 只有 `COMPLETED` 才解析结果地址；未完成调用 `fetchTranscription` 返回 **409 PROCESSING** |
| 已完成但缺 `Result.Transcription` | 视为契约异常，明确报错（不静默当成空转写） |
| 业务错误码被忽略 | `Code` 非 0/200 时抛错并带出 `Message` |
| 说话人人数固定 2 | 默认**不指定**（`diarization-speaker-count: 0`），交由云端声学聚类判断，避免把多人通话强行切成两人 |
| SDK 依赖 | 保持 `tingwu20230930:2.0.0` **不升级**：强类型模型缺 `Result`，我们走通用 `callApi` 拿原始响应体，升级无收益且有回归风险 |

另外新增 `TingwuApi` 端口（真实 SDK / 桩 / 未配置三态），与对象存储同一策略：
**凭据未配置就 503，不伪造任务号或转写结果**。

## 2. 转写解析（`TranscriptionParser`）

- 按**时间**排序重建连续段落，同时间戳保持原始顺序，`sequence` 从 1 连续编号；
  **不按 speaker 把整篇拼成一段**（同一说话人的多段保持独立）。
- 每句保留：`speakerId`（未知留空，**不写 0**——0 是合法聚类标签）、毫秒起止、原文
  （词 + 标点逐字拼接，标点与无标点句都原样保留）、词级明细（供 S07 做 UTF-16 偏移映射）。
- 严格模式：缺 `Transcription`/`Paragraphs`/`Words`/`Start`/`End`、时间戳倒挂、`SpeakerId` 非数字
  一律抛 `TranscriptionParseException`（422 + 明确文案），**不做候选键猜测、不填 0**。
- 空音频（`Paragraphs` 为空）返回空结果而不是异常，由调用方判定 `INVALID`。
- 结果体积上限（默认 20 万词）与下载体积上限（8MB）双重保护。
- `durationMs` 是结果覆盖时长（最晚结束时间），不等于容器时长；真实时长以 S14 云端核验为准。

## 3. 可信下载（`TranscriptionDownloader` + `ResultUrlPolicy`）

- 只允许 **HTTPS**，拒绝带凭据的 URL、`localhost`/`metadata`/`.internal`，以及解析到
  回环、私网、链路本地、组播、`0.0.0.0` 的地址。
- 重定向**不自动跟随**：每一跳重新过策略，最多 2 次。
- 体积上限 8MB、连接与读取超时 5s/15s；非 2xx 明确报错。
- 下载地址与内容都不写日志（避免泄露签名链接与原文）。

> 测试期间发现并修掉一个真实漏洞：JDK 的 `isSiteLocalAddress()` 只覆盖 IPv6 的 `fec0::/10`（已废弃），
> **`fc00::/7` 唯一本地地址会被放行**。已补 `isUniqueLocal` 判定，测试用例包含 `fd00::1`。

## 4. 状态映射与管线边界

远端 `QUEUEING/ONGOING/COMPLETED/FAILED` → `RemoteStatus{QUEUED,RUNNING,COMPLETED,FAILED,UNKNOWN}`，
未知状态**保持现状**，绝不当作成功。`RecognitionTaskService.applyRemoteStatus` 只更新任务状态：

- 转写结果的下载、解析、按时间序落库属于 **S06 持久作业管线**（队列 + 租约 + 事务发布），
  不在请求路径里做；本轮把 `TingwuService.fetchTranscription(TaskInfo)` 备好供 S06 调用。
- 回调入口只按回调里的状态唤醒（不使用回调携带的结果地址），这与开发文档 §5.3
  「不信任请求内任意结果 URL」一致。
