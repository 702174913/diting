**结论摘要**：后台统计面收敛为**总览看板一个**。除 `/overview` 外的六个统计页
（增长与留存、财务与单位经济、质检运营、违规图谱、质量与准确率、合规风控）连同其
前端页面、路由、侧栏入口、后端统计分组、只服务于它们的 mapper 方法与
`GET /api/admin/ops/queue` **整体删除**；管理类页面（录音资产、规则库、策略设置、
协议配置、权限与审计、账号管理）与总览看板本身**未改**。

删除是纯代码删除：不动数据库表、不写迁移、不删数据。回滚 = 从文件级备份还原（见文末）。

## 1. 删除清单

| 层 | 删除对象 |
| --- | --- |
| 前端页面 | `views/{growth,finance,ops,map,quality,compliance}/index.vue`（6 个目录整体删除） |
| 前端路由 | `router/index.ts` 中 6 条 route；旧地址由兜底 `/:pathMatch(.*)*` 跳回 `/overview` |
| 前端入口 | 侧栏菜单项与随之无用的 5 个图标 import；`stores/view.ts` 的 `IR_LOCKED` 去掉 `ops`/`map` |
| 前端文案 | 投资人横幅不再提「质检运营、违规图谱明细」；改为「录音资产明细、权限审计、账号管理与协议配置已锁定」 |
| 前端接口 | `api/stats.ts` 删 `QueueItem` 与 `fetchOpsQueue` |
| 前端键集 | `MetricsPanel.vue` 的 `LOWER_IS_BETTER` 只留总览真会出现的键；`DIRECTION_NEUTRAL` 收敛为空集（判断逻辑保留） |
| 后端分组 | `StatsService` 删 `ops/compliance/violations/growth/quality/finance` 六个 section 方法，705 → 270 行 |
| 后端 helper | 删只被它们使用的 `financeMetrics/queueTotalByStatus/avgSecondsOf/statusLabel/toRows/fillByHour/trendRows` |
| 后端 SQL | `StatsMapper` 删 28 个方法（含本就无人调用的 `exportByStatus`），314 → 108 行 |
| 后端接口 | `AdminOpsController` 删 `GET /api/admin/ops/queue`、`QueueItem`、`mask()`、`elapsedSeconds()`；`AdminController` 删占位端点 `/growth`、`/finance` |

保留的判断依据（都经引用反查确认）：

- `StatsMapper.queueByStatus`：总览「当前队列」经 `queueTotal()` 使用 —— 曾疑为 ops 专属，实测必须留。
- `AdminController.dashboard`：仅返回 `{deprecated:true}`，被 `AdminEndpointSecurityTest` 当权限探针用 4 处（401/403/三角色可读/禁用账号），因此保留并改注释；A/B 验证过它不是本次失败原因。
- `AdminOpsController.reconciliation` 与 `queueLimit()`：核销对账用，与统计页无关。
- `MetricsPanel.vue`：只服务总览，保留（未收紧 `section` prop 类型，避免无谓接口变更）。
