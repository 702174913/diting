# S08 角色确认与版本化报告 · 记录

版本：v1.0 · 日期：2026-09-24 · 阶段：S08
规格依据：[开发文档](./开发文档.md) §5.2 状态机、§6.3 规则与报告、§7.2 接口、§8 角色与计分；[开发计划](./开发计划.md) §11 S08。

**结论摘要**：speakerId 与业务角色分离，角色确认带 `expectedRevision` 乐观锁；
每次确认触发重算并生成**新的报告版本**（历史版本始终可读），报告发布后才把任务置为 `COMPLETED`；
前端改为按服务端给的原文区间高亮，并移除了没有来源的「转写完整度」。验证：
**170 项单元/切片测试**（S08 新增 10 项）+ **32 项端到端断言**全部通过。

## 1. 角色映射（`speaker_mappings`）

- 一次确认写入**一整组**映射（speakerId → AGENT/CUSTOMER/UNKNOWN），共享同一个 `revision`。
- `expectedRevision` 与当前版本不一致 → **409**，且不写入任何行：两个人同时改角色不会互相覆盖。
- 允许 `UNKNOWN`：**多人通话不强行二分**（E2E 用三位说话人验证过），未确认时前端按「说话人 A/B」展示。
- `confirmedBy` + `confirmedDomain` + `confirmedAt` 落库，C 端与后台共用同一套契约（后台入口属 S10）。

> **现状（2026-09-27 核查）**：角色确认的 HTTP 入口在代码里已不存在——`ReportController` 只剩
> `GET /{id}`，`AdminRecordingController` 只剩 4 个 GET/DELETE，`ReportService.saveMapping` 与
> `SpeakerMapRequest` 没有任何调用方；`speaker_mapping_confirmed` 全仓库只有建任务时写 `false`。
> 结果是 `speaker_mappings` 始终为零行、所有报告都是 `mapping_revision=0`。
> 因此目标角色功能已隐藏（判读一律按「任意角色」，见 [S07 §4](./S07-规则库与判读记录.md)、
> 开发文档 §8）；本节描述的实现仍在仓库里，恢复路由后即可重新启用。
> 同时注意 `src/test/resources/{report,admin,export,lifecycle}/*.sh` 仍在调
> `POST /api/report/{id}/speaker-map` 与 `POST /api/admin/recordings/{id}/speaker-map`，这两条路由需要一并恢复，
> 否则那批 e2e 脚本跑不过。

## 2. 版本化报告（`report_versions` + `violations`）

```text
角色确认 → 冻结规则集合快照（S07）→ 取句子与角色 → 规则引擎判读
        → 同一事务写入 report_versions(ANALYZING) + violations → 置 PUBLISHED
        → 之后才允许把任务推进到 COMPLETED（S06 的守卫）
```

- 版本号只增不减：重算**新增**版本，旧版本行与证据都不动，`GET /api/report/{id}?version=N` 可回读。
- 每次版本都记录快照：`rule_set_version`、`mapping_revision`、`threshold_snapshot`、`config_version`。
- **失败语义**：分析失败时事务整体回滚（不留半份新报告），另起独立事务记一条 `FAILED` 版本；
  读取时优先返回**最近一次成功发布**的版本，并在 `latestStatus` 与 `notes` 里说明
  「最新一次重算未完成（FAILED），当前展示第 N 版」——不把旧报告冒称新版。

## 3. 读取契约（`ReportDetailResponse`）

| 字段 | 口径 |
|---|---|
| `reportVersionId / reportVersion / status / latestStatus` | 当前展示版本与最近一次分析状态（两者可不同） |
| `speakerMapping / rolesConfirmed` | 角色映射与是否已确认；未确认时角色为空 |
| `sentenceCount / flaggedCount / violationCount` | `flaggedCount` 按命中**句子**去重；`violationCount` 含通话级缺失项，因此二者可不等 |
| `riskScore / complianceScore / threshold / riskFlagged` | **未发布时为 null**（不伪造 0）；`riskFlagged = riskScore >= threshold` |
| `sentences[]` | 时间序；带 `sequence`、`speakerId`、`role`、`highlights`（原文 UTF-16 左闭右开）、`notes` |
| `violations[]` | 规则版本、规则名、匹配类型、证据句、`ranges`、扣分与说明；缺失项 `sentenceId` 为 null |
| `audioAvailable` | 原件是否仍在保留期；**false 只影响音频，不影响文本与报告可读**（REPORT-08） |
| 已移除 | `accuracy`（转写完整度）——没有可靠来源，按开发文档要求删除 |

服务端只返回文本与区间，**不生成 HTML**；XSS 文本原样透传由 E2E 断言（`<script>` 出现在响应里）。

## 4. 前端适配（小程序）

- `SentenceItem.vue`：按 `highlights` 区间切分渲染（越界/重叠区间自动退化与跳过，绝不瞎切），
  显示「说话人 A/B」或已确认的角色标签，逐条展示 `notes`。**不使用 v-html**。
- `pages/report/detail.vue`：去掉「转写完整度」；新增风险分与阈值、违规数（含缺失项）、
  报告版本与状态、报告 notes（含角色未确认 / 重算失败 / 原件已清理三类提示）；
  新增角色确认区（点击切换角色 + 提交，走 `expectedRevision`）。
- 文案沿用「不构成法律意见，不作为处理结果承诺」，未出现「完全合规」式断言；
  无命中时的说明是「没有命中这次启用的规则」。
