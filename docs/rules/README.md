1. 后台 → 规则库 → 批量导入 → 选择本文件（或粘贴全文）；

3. 落库是**逐行独立事务**、同 code 走乐观锁追加新版本，单行失败不影响其他行。

## 已知边界（业务需确认）

1. **must-have 是通话级必需项**：45s 与 10s 合规样本的 20 分来自「未告知录音」「未询问还款能力」，
   这两项在两段样本里**确实没有出现**（属真缺失，不是误匹配；样本自述的合规清单也不含这两项）。
   若不认可其必需性，导入后在后台停用这两条即可 —— 停用只影响未来判读。
   短通话（10s 样本仅 4 句）天然会集中命中通话级缺失项，业务评估时应按通话时长看。
2. **角色未确认时**：31 条里 26 条角色依赖规则会被跳过（`skipped` 显式说明），
   只有 5 条 `ANY` 规则参与判读，因此角色确认是判读质量的前置条件。
3. **未覆盖**：48s 样本埋点 4「全篇未做身份核实、未告知可协商渠道」本批没有对应条目。
4. **扣分权重与规则依据均为草案**：规则说明只写平台/行业自律口径，不写法律结论（对齐开发文档 §8）。
   每条 description 末尾都标注「扣分权重待业务确认」。
5. **历史遗留快照**：`rule_sets` id=24 仍引用已删除的规则版本 1001–1016，该快照无法复算。
   与本批导入无关，但建议业务知悉。

## 复现方式

本文档的验证不落库、不改代码，用生产类跑：

```bash
# 1. 解出已构建产物的 classpath（BOOT-INF/classes + BOOT-INF/lib/*.jar）
```
