# S02 鉴权与双端接口基础 · 记录

版本：v1.0 · 日期：2026-09-24 · 阶段：S02
规格依据：[开发文档](./开发文档.md) §7 API 契约、§9 权限与隐私；[开发计划](./开发计划.md) §5 S02。

**结论摘要**：后台占位登录已移除，改为 `admin_users` + BCrypt 真实校验；C 端与后台拆成两个
独立身份域（JWT 带 `aud` 与域声明），白名单收紧到只剩登录接口与听悟回调；权限矩阵落在服务端
拦截器上。验证：**45 项单元/切片测试 + 40 项端到端断言 + 11 项前端请求层断言**全部通过。

## 1. 身份域与令牌

| 项 | C 端用户 | 后台账号 |
|---|---|---|
| 令牌 audience | `diting-user` | `diting-admin` |
| 域声明 | `domain=USER` | `domain=ADMIN` |
| 主体 | `users.id` | `admin_users.id` |

- 签发与校验都在 `TokenService`：解析时同时校验 issuer、audience 与域声明，任一不符即拒绝。
- 拿到**另一身份域的有效 token** 时返回 **403**（已登录但登错域），token 无效或过期才返回 **401**。
- **旧 token 一律失效**：改造前签发的 token 没有 `aud`/`domain`，重启后客户端会收到 401 并重新登录
  （开发计划 S02 要求的“旧 token 域无法区分时明确失效策略”）。小程序端会自动静默重登。

## 2. 接口白名单（收紧后）

| 路径 | 是否需要登录 |
|---|---|
| `POST /api/auth/wechat`、`/register`、`/login` | 否 |
| `POST /api/admin/login` | 否 |
| `POST /api/callback/tingwu` | 不走用户 token（回调按听悟协议自校验，S06 落地） |
| `POST /api/auth/bind-wechat`、`GET /api/auth/userinfo` | **是**（此前在白名单里，能未登录拿到 200） |
| 其余 `/api/**` | 用户 token |
| 其余 `/api/admin/**` | 后台 token，且每次请求回库复核启用状态与角色 |

## 3. 错误信封与业务码

响应统一为 `{code, message, data, symbol}`：成功 `code=0` 且 `symbol` 为空；失败时 **HTTP 状态码与 `code` 一致**，`symbol` 供客户端判分支。全局异常处理器把参数类错误从 500 纠正为 400（缺参、类型不匹配）。

| 码 | symbol | 场景 |
|---|---|---|
| 400 | `BAD_REQUEST` | 参数校验失败、缺必填参数、类型不符 |
| 401 | `LOGIN_FAILED` | 账号或密码错误（不区分账号是否存在） |
| 401 | `UNAUTHORIZED` | 未登录、token 过期或伪造 |
| 403 | `FORBIDDEN` | 身份域不符、角色不足 |
| 403 | `ACCOUNT_DISABLED` | 后台账号被禁用（含已签发 token 立即失效） |
| 404 | `NOT_FOUND` | 资源不存在或归属不符（不泄露存在性） |
| 409 | `CONFLICT` / `ROLE_UNCONFIRMED` / `PROCESSING` | 状态冲突；后两者留给 S08/S06 |
| 422 | `UNPROCESSABLE` / `FAILED` | 格式/参数不合法、密码强度不足 |
| 429 | `TOO_MANY_REQUESTS` / `QUOTA_EXCEEDED` | 登录失败保护、限流；额度留给 S03 |
| 503 | `NOT_CONFIGURED` | 云服务未配置（S04/S05 使用，禁止返回模拟数据） |

`QUOTA_EXCEEDED`(429)、`ROLE_UNCONFIRMED`(409)、`AUDIO_EXPIRED`(404)、`PROCESSING`(409)、`FAILED`(422)、`NOT_CONFIGURED`(503)
本轮只定义，由 S03/S06/S08/S11 使用——契约先固定，避免各阶段各造一套码。

## 4. 权限矩阵（服务端强制）

| 能力 | 用户 | ADMIN | OPERATOR | INVESTOR | 强制点 |
|---|---|---|---|---|---|
| 聚合看板 `GET /api/admin/dashboard|growth|finance` | — | ✅ | ✅ | ✅ | `@RequireRole` |
| 账号管理 `GET/POST/PUT /api/admin/accounts` | — | ✅ | ❌ | ❌ | `@RequireRole(ADMIN)` |
| 本人任务/报告 | ✅ | — | — | — | 查询条件带 `user_id`、`requireOwned` 404 |
| 他人任务/报告 | ❌ 404 | — | — | — | 同上 |

- 角色**每次请求回库复核**：`admin_users.enabled=false` 后，已签发的 token 下一次请求即失效（403 ACCOUNT_DISABLED）；角色被改也立即按新角色判权。
- 前端菜单/路由只是可见性，改 URL 或前端切换视图都不构成权限——AUTH-04 已用“用户 token 调后台接口”验证。
- `DELETE /api/task/{id}` 现在先做归属校验（不是本人一律 404）；真正的墓碑与异步清理属于 S13。

## 5. 契约变更（对两端的影响）

| 变更 | 之前 | 现在 | 客户端适配 |
|---|---|---|---|
| C 端登录响应 | `{token,userId,nickname,hasPassword,hasWechat,newUser}` | `{token,userInfo:{id,username,nickname,hasPassword,hasWechat},isNewUser}` | 小程序 `types/api.ts` 本来就是这个形状，服务端对齐它 |
| `bind-wechat` | 返回 `{hasWechat}` | 返回 `UserInfo` | 小程序 `api/auth.ts` 声明是 `UserInfo`，已对齐 |
| `userinfo` | 未实现，返回 `{}`（且不需要登录） | 真实 `UserInfo`，未登录 401 | 同上 |
| 后台登录 | 占位：任意账号拿 OPERATOR | `admin_users` 真实校验 | 后台登录页改为透传服务端 message（禁用/限流都有明确文案） |
| 失败响应 | 一律 HTTP 200 + 信封 code | HTTP 状态 = 信封 code | 两端 request 层都能从 `error.response.data` 读回信封，不再只剩一句“请求失败(HTTP 401)” |
| 分页 | 无 | `{items,total,page,pageSize}`，page 从 1 起、默认 20、上限 100、越界 422 | 账号管理接口已按此实现 |

前端补充：两端新增 `utils/authToken.ts` 统一登录态读写，`api/request.ts` 默认注入存储中的 token，
401 时清登录态——小程序回调 store 清内存状态，后台整页跳登录页（避免与 router 形成循环依赖）。

## 7. 决策与偏离

| 项 | 处理 | 理由 |
|---|---|---|
| 登录失败保护实现 | 进程内计数（5 次 / 10 分钟，按 域+账号+IP） | 单实例足够；多实例部署需换共享存储，已在此登记 |
| 分页适用范围 | 本轮只在新接口（账号管理）启用；`/api/task/list` 仍是数组 | 改它必须同时改小程序页面，而页面属于 S09 范围；`PageQuery/PageResult` 已备好，S09 直接用 |
| 任务状态枚举 | 仍是旧值（PENDING/ONGOING…） | 与 S01 的决定一致：与 S06 状态机、两端展示同批发布 |
| 审计写入 | 账号变更暂不写 `audit_log` | 审计动作码与 detail 结构属 S10；表已在 S01 建好 |
| 凭据环境化 | 新增的后台初始密码走 `DITING_ADMIN_INIT_USERNAME/PASSWORD`（无默认值）；`application.yml` 里既有的 JWT/数据库密码未改动 | 改动既有密码位置会让本地实例起不来；按 §11「配置与运行准备」与部署配置一并处理 |
| `@MapperScan` 位置 | 从启动类移到 `MybatisPlusConfig` | 启动类带 `@MapperScan` 会让 `@WebMvcTest` 切片要求 `SqlSessionFactory`，Web 层测不起来 |

  否则库中没有 ADMIN，后台无人能登录——系统不会创建任何默认密码账号。
