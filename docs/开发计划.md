# 谛听分步开发计划与测试验收要求

版本：v1.0 · 日期：2026-09-24。

配套规格：[开发文档](./开发文档.md)。本轮仅交付文档S00；S01—S14为未来软件实施工作，不代表已经开发或测试通过。开始业务代码实施需另行授权。

## 1. 执行原则

每一步先核实当前代码和未提交改动，遵守就近AGENTS.md；不覆盖并行会话成果。保持谛听UI、OSS预签名PUT+通义听悟、不接LLM的决策。不能直接搬旧项目代码或密钥。

先建立数据与身份边界，再做上传、转写、规则、报告；最后接导出、统计、生命周期与真实云门禁。离线fixture允许先行，但不是云服务成功证据。没有云凭据时不伪造完成状态。

禁止全量运行ts:check、lint:eslint、build:local、npm test、未限定的mvn test。文档任务不运行构建、不启动浏览器、不创建云任务、不初始化Git。

```text
                            ↓

                            ↓

```

依赖表是准入依据，编号是推荐执行顺序。S06/S07可在契约稳定后并行；S09/S10可按目录隔离并行。公共DTO/数据库/服务端文件只能一个写入者负责，不能并行互相覆盖。S12不依赖导出功能本身，但按编号推进更便于验收。

真实云POC在S14集中验收，S04已提前设置上传支持边界为技术风险；如发现微信PUT方案不可行，应停止相关实现并报告，不自行更换上传架构。

## 14. S11 PDF与ZIP异步导出

**验收要求**：PDF无乱码漏字且可读；ZIP可解压，不调用openDocument打开ZIP；导出错误有状态；报告版本/权限/期限一致。

**交付物**：模板、导出服务、PDF/ZIP样例测试产物（仅授权测试数据）、测试报告。

**失败/阻塞处理**：脱敏未定不发布敏感导出；字体授权或渲染失败先选合规兼容方案并记录，不能返回空PDF当成功。

## 16. S13 删除与30天生命周期

**前置条件**：S06墓碑基础、S10权限、S11导出通过。

**修改范围**：PrivacyController、TaskController、清理scheduler、OSS/导出清理服务及job mapper。

**按顺序做**：
1. 从上传时间计算30天原件期限，授权路径在到期瞬间拒绝，不等待定时任务真正删除。
2. 定时清理原件、含音频ZIP、孤立上传；保留可重试任务。
3. 单条/全部删除传播到句子、命中、报告、导出和对象；先不可访问再清理。C端以`GET /api/deletions/{deletionJobId}`查询本人作业，ADMIN以`GET /api/admin/deletions/{deletionJobId}`查询授权范围作业；只返回状态/计数/安全摘要。状态为QUEUED/RUNNING/RETRY_WAIT/COMPLETED/FAILED，后台有限退避重试，重复原删除请求幂等唤醒同一作业，不能恢复资源可见性。
4. 导出/角色重算/迟到回调在提交前检查墓碑。
5. 最小审计、告警与失败重试；核实云端任务结果删除能力与隐私披露。
6. 文本/审计保留时长未确认前，不宣称全部30天删或永久存储。

**测试**：DELETE-01期限前后边界；DELETE-02OSS部分失败；DELETE-03重复删除；DELETE-04下载/导出并发；DELETE-05删除后回调；DELETE-06服务重启恢复；DELETE-07音频ZIP副本过期；DELETE-08抹除后用户及后台不可读。

**验收要求**：到期立即停止新授权；清理失败可重试/告警；已标删除资源不会被重新发布；隐私说明诚实描述云端及下载副本限制。

**交付物**：清理服务、竞态/到期测试、隐私文案与清理日志样例（无敏感内容）。

**失败/阻塞处理**：对象删除失败保留清理记录，不直接删掉唯一定位信息；云端不可删除要明确披露并由上线决策处理。
