# S13 删除与 30 天生命周期 · 记录

版本：v1.0 · 日期：2026-09-24 · 阶段：S13
规格依据：[开发文档](./开发文档.md) §5.3 并发与恢复、§9 权限与隐私、§7.2/§7.3 接口；[开发计划](./开发计划.md) §16 S13。

**结论摘要**：原件保留期从**上传时间**起算 30 天，到期瞬间拒绝新授权（不等定时任务真删）；
清理执行器把删除传播到句子/命中/报告/导出与对象，失败有限退避重试、超限标 FAILED 并打 ERROR 告警；
清理作业有**租约**，进程崩溃后可被重新领取。验证：**176 项单元/切片测试** + **39 项端到端断言**全部通过。

---

## 1. 保留期与到期边界

- 提交任务时写入 `expires_at = 上传会话创建时间 + 30 天`（`diting.retention.audio-days`），
  **不随提交时间漂移**。
- 所有签发原件的路径在到期那一刻就拒绝：`AUDIO_EXPIRED`（404 语义），不等待清理任务真正删除对象。
- 到期清理只做两件事：**删除对象** + 标记 `audio_purged=1`、清空 `oss_object`。
  **文本保留时长未确认前不动文本** —— 因此文档里不写「全部 30 天删除」，只写「原件 30 天」。

## 2. 清理执行器（`RetentionService`）

一轮 `tick()` 做四件事：删除作业 → 到期原件 → 孤立上传 → 到期产物。

| 目标 | 动作 |
|---|---|
| 单条删除（TASK） | 对象 → 导出产物（含含音频 ZIP）→ 命中 → 报告版本 → 句子；任务行保留**最小墓碑**（`deleted_at` + 状态，`oss_object` 置空） |
| 全部抹除（ERASE） | 本人所有任务 + 孤立上传会话；**账号匿名化**（清空 username/password_hash/openid/unionid，昵称置「已注销」），不删用户行以免 token 与审计悬空 |
| 到期原件 | 删对象 + `audio_purged=1` + 清空对象引用 |
| 孤立上传 | 超过 `cleanup_after` 仍未登记的会话：删对象 + 删会话行 |
| 到期产物 | 删产物对象 + 清空 `artifact_key`（作业行保留供追溯） |

- **失败与重试**：清理由 CAS 领取（`status + next_attempt_at`），失败 → `RETRY_WAIT` 退避重试，
  超限 → `FAILED` 并打 **ERROR 日志**（作为告警接入点）+ 记一条 `DELETION_FAILED` 审计。
- **崩溃恢复（DELETE-06）**：`next_attempt_at` 兼作**租约到期时间**，`RUNNING` 且租约过期的作业
  会被下一轮重新领取；租约未过期的不会被抢——不额外加列，与任务管线同一套思路。

## 3. 可见性优先与删除传播

- 删除请求写入墓碑那一刻起：C 端报告/状态、后台详情、导出创建全部 404（「先拒绝读，清理异步」）。
- 迟到回调：已删除任务直接忽略且返回 200，不复活数据（DELETE-05）。
- 导出/角色重算在提交前都复查墓碑（S11 已实现，S13 保持）。

## 4. 接口

| 方法/路径 | 权限 | 说明 |
|---|---|---|
| `DELETE /api/task/{id}` | 本人 | 墓碑 + 幂等登记清理作业 |
| `DELETE /api/privacy/erase` | 本人 | 全部抹除（含账号匿名化） |
| `GET /api/deletions/{jobId}` | 本人 | 状态/计数，最小元数据 |
| `GET /api/admin/deletions/{jobId}` | 仅 ADMIN | 后台授权范围内查询清理状态 |

状态流转：`QUEUED → RUNNING → COMPLETED / RETRY_WAIT →（退避后）RUNNING → … / FAILED`。

## 5. 测试与证据

| 层 | 用例 | 结果 |
|---|---|---|
| 端到端 | 独立库 `diting_s13_test` + 8902 实例：DELETE-01～08（到期边界、清理传播、重试、崩溃恢复、迟到回调、ZIP 副本、抹除后双方不可读） | **39 项通过** |
| 回归 | 服务端 176 项单元/切片测试 | 通过 |

**E2E 抓到的三个真实缺陷（已修）**：

1. **`deletion_jobs` 没有 `updated_at` 列**：新增的状态 CAS 语句写了该列，运行时直接 500
   （S01 建表时未含此列）——编译期无感，只有跑起来才暴露。
2. **RUNNING 作业永不恢复**：清理作业没有租约，进程崩溃后作业卡在 `RUNNING` 再也不会被处理 ✗
   与「服务重启恢复」要求相违。已用 `next_attempt_at` 兼作租约并补了正反两个用例。
3. **账号匿名化其实没清 PII**：MyBatis-Plus 的 `updateById` 默认**跳过 null 字段**，
   置空 username/openid 的写法静默失效（回读仍是原值）。改为显式 `UPDATE ... SET x = NULL` 的
   `UserMapper.anonymize`，并在方法注释里写清这个陷阱。

另外修了一处语义：过期产物此前返回 409「未完成」，现在先判过期返回 **404**（对用户而言就是不存在）。

证据文件（`docs/evidence/S13/`）：`java-tests-*.log`（176 项）、`e2e-lifecycle-*.log`（39 项）。
复现见 `diting-server/src/test/resources/lifecycle/README.md`。
