## 2. 服务器与域名准备

1. **服务器**：JDK 17（后端编译目标 17；当前生产是 macOS，建议迁到 Linux 常驻机，避免系统字体/路径依赖）。
2. **Maven**：仓库内**没有 `mvnw`**，服务器需自备 Maven 3.9+ 与 JDK 17。
3. **MySQL**：8.0 或 9.x（迁移脚本用 `utf8mb4_0900_ai_ci`，需 MySQL 8+）。
4. **域名与证书**：
   - 一个业务域名（例：`api.example.com` 或统一用 `diting.example.com`）→ **必须 HTTPS**，小程序与回调都要求。
   - 大陆服务器需完成 **ICP 备案**，证书用可信 CA（Let's Encrypt 或商业证书均可）。
   - **部署形态建议：同源**。后台静态文件与 `/api` 挂在**同一个域名**下（后台直接走同源相对路径，见 §6）。
5. **不得暴露**：MySQL 3306、后端 8080 仅监听本机或内网，由反代对外。

### 3.1 缺了会**启动即失败**（无默认值，故意如此）

| 变量 | 说明 |
|---|---|
| `DITING_DB_PASSWORD` | 数据库密码。**必须轮换成新值** |
| `DITING_JWT_SECRET` | JWT 签名密钥。**必须 ≥32 字节随机值**（当前 15 字节会被 jjwt 拒绝） |

生成示例（在服务器本地执行，不要粘进聊天）：

### 3.2 生产必须显式提供（否则对应功能返回 503 `NOT_CONFIGURED`）

| 变量 | 缺省值（当前） | 后果 |
|---|---|---|
| `DITING_DB_USERNAME` | `root` | 建议改用**最小权限业务账号** |
| `DITING_ALIYUN_ACCESS_KEY_ID` / `DITING_ALIYUN_ACCESS_KEY_SECRET` | `请替换` | 上传/转写/OCR 全部 503 |
| `DITING_OSS_BUCKET` | `请替换` | 上传 503。**bucket 名不得含点号**（历史已踩坑） |

| `DITING_PUBLIC_BASE_URL` | 空 | 启动日志无法提示管控台该填的回调地址 |

## 4. 数据库

> **结论先给**：线上要带生产数据 → **直接 dump 导入**（一步到位，不必跑迁移脚本）；
> 只有**空库且没有这份生产数据**时，才走 §4.2 的 `schema.sql` + V2…V11 逐个执行。
>
> ⚠️ **不能用现有那份备份当导入源**：`~/.diting-business-backups/diting-20260927T012227Z/`（09:25）
> 是 **V7 之前**导出的，只有 21 张表，缺 V7–V11；服务不允许在缺这 5 个迁移的库上启动。
> 导入源必须是**迁移完成后重新导出**的当前生产库 dump。

### 4.1 生产库（已有数据）——**不要重跑迁移**

V2–V11 已执行。上线窗口只需：
1. **只读核对**：`SELECT version FROM schema_migrations ORDER BY version;` 应为 10 行且版本唯一；
   核对 `task_assets.uk_asset_upload`、`users.erased_at`、OCR/导出/清理租约列均存在；确认表共 22 张。
2. **导出当前生产库**（停写后，含 schema/data/routines/triggers/events，单事务一致性）：
   ```bash
   mysqldump --single-transaction --routines --triggers --events \
     --protocol=TCP --host=127.0.0.1 --port=3306 --user=<user> --databases diting > diting-<日期>.sql
   chmod 600 diting-<日期>.sql && shasum -a 256 diting-<日期>.sql > SHA256SUMS
   ```
   > 坑：MySQL 9.x 的 `mysqldump` 不认 `--connect-timeout`（历史已踩，退出码 7）。
3. **导入目标库**（这就是「直接导进去」，等价于一次性完成结构+数据+迁移台账）：
   ```bash
   # 库名同为 diting 时可直接导；换库名要先剥掉 dump 里的 CREATE DATABASE / USE
   sed -e '/^CREATE DATABASE/d' -e '/^USE /d' diting-<日期>.sql | mysql -h<host> -u<user> -D<目标库>
   ```
   导入后核对：**表 22 张**、`schema_migrations` **10 行**版本唯一、抽样行数与源库一致。
   > 版本要求：dump 源是 MySQL 9.3，目标建议 8.0.x / 9.x；**不要 9 → 8 降级**（如必须降级需单独验证）。
   > 隐私：真实用户数据会随之搬进目标环境——目标为生产可接受，若为测试环境须先脱敏。
   > 该操作**不需要**再跑 V2–V11 脚本（台账随数据一起恢复）。
4. **最小权限账号**：业务账号只授权 `diting` 库的 DML + 迁移所需的有限 DDL，不用 `root`。
5. **历史遗留裁决**：`export_jobs` 4 行 FAILED（含 1 行 `attempt_count=3 / EXPORT_FAILED`）。
   注意**导入会把这几行原样带过去**，所以上线前仍须业务方给出处置结论；
   先保全日志与 OSS/账单证据，**不得自动重置、补发或还原**。

### 4.2 全新环境（干净库）初始化 —— **仅当目标库为空且不导入生产数据时**

`sql/schema.sql` 只是**旧基线（V1）**，不含 V2–V11 的对象（无 `schema_migrations`、无租约/唯一键/抹除列）。
干净库必须按顺序执行：

```bash
# V1 基线 → V2 起逐版本，顺序不可乱、错误即停（不要用 mysql --force）
mysql -h<host> -u<user> -D<库名> < sql/schema.sql
for v in V2__S01_schema_foundation V3__S06_status_migration V4__S16_media_assets \
         V5__S18_account_soft_delete V6__S19_agreements V7__quality_write_guards \
         V8__quality_ocr_leases V9__quality_export_leases \
         V10__quality_user_erase_revocation V11__quality_deletion_fencing; do
  mysql -h<host> -u<user> -D<库名> < sql/migration/$v.sql
done
```

> **坑**：`schema.sql` 含 `CREATE DATABASE ...; USE diting;`，若目标是别的库名，
> 先剥掉再加载，否则测试数据会写进真实库：
> `sed -e '/^CREATE DATABASE/d' -e '/^USE /d' sql/schema.sql | mysql -D <库名>`
>
> **坑**：`V6__S19_agreements.sql`（约 100KB）含条款正文，执行前确认字符集为 `utf8mb4`。
>
> **坑**：迁移脚本含 `DELIMITER` 与存储过程，**必须用 `mysql` 命令行客户端**执行（图形工具/驱动常失败）。
>
> MySQL DDL 隐式提交：部分成功不能直接重跑，先查 `information_schema` 与 `schema_migrations` 再人工补救。

```bash
cd diting-admin

```

- 路由用 `createWebHistory()` → 反代必须做 SPA 回退（见 §6），否则刷新任意子路由 404。

### 5.3 用户端 diting-app

构建脚本 `scripts/build-production.cjs` 会**强制校验**，不满足直接拒绝构建：

| 目标 | 命令 | 必需环境变量 |
|---|---|---|
| 微信小程序 | `npm run build:mp-weixin` | `VITE_BASE_URL`（https 真实域名，**仅源站、不带路径**）、`DITING_WECHAT_APPID`（`wx`+16 位十六进制）、`DITING_UNI_APP_ID`（`__UNI__` 开头） |
| H5 | `npm run build:h5` | `VITE_BASE_URL`（https 真实域名） |

- 校验规则：非 HTTPS、含用户名密码/查询串/锚点、`example.com`、`localhost`、`127.0.0.1` 一律拒绝。
- 可用 `--validate-only` 先做**离线格式校验**（不联系域名、不编译）：
  ```bash
  VITE_BASE_URL='https://api.example.com' DITING_WECHAT_APPID='wx0123456789abcdef' \
  DITING_UNI_APP_ID='__UNI__ABCDEF1' node scripts/build-production.cjs mp-weixin --validate-only
  ```
- 脚本会临时把真实 appid 写进 `src/manifest.json`，构建结束**自动还原**；请确认仓库最终提交的 `manifest.json`
  仍是空 appid（避免把 appid 提交进版本库）。
- 产物：`dist/build/mp-weixin`（小程序，用微信开发者工具上传）、`dist/build/h5`（H5）。
- H5 的托管位置需与 `VITE_BASE_URL` 的**接口域名区分**：H5 页面自身放在静态托管/反代目录，接口指向 API 域名；
  微信内 H5 还需在公众平台配置业务域名/JS 安全域名。

## 6. 运行时与反向代理

建议形态（同源，避开 CORS 改造）：

```
浏览器 ──https──> 反代（443）
                   ├── /            → diting-admin/dist 静态文件（SPA 回退 index.html）
                   ├── /api/…       → 127.0.0.1:8080（后端）
                   └── /api/callback/tingwu[/token] → 127.0.0.1:8080（听悟回调，公网可访问、POST）
```

反代要点：
1. **SPA 回退**：`try_files $uri $uri/ /index.html;`（后台用 history 路由，不做回退则刷新 404）。
2. **回调路径必须公网可达**，且与 `DITING_PUBLIC_BASE_URL` + `diting.tingwu.callback-path` 拼出的地址一致。
   当前回调用**路径令牌**（`/api/callback/tingwu/{token}`）而非验签字段，令牌走环境变量，不写文档。
   管控台里按项目配置该地址（官方契约是 HTTP POST 回调）。
3. **上传体积**：录音单文件上限 50MB（`diting.media.max-size-bytes`），反代 `client_max_body_size` 需大于该值；
   实际音视频是**直传 OSS**（预签名 PUT），反代只承接签名与登记等小请求。
4. **超时**：导出/长任务为异步作业，接口本身快；仍建议 `proxy_read_timeout` 给足（≥60s）。
5. **健康探针**：项目**未引入 actuator**，没有 `/actuator/health`。用公开接口做探活：
   `GET /api/agreements`（无需登录）返回 200 即视为进程与 DB 通路正常。
6. 后端只监听 `127.0.0.1:8080` 或内网，不直接对外暴露。

## 7. 微信 / 小程序侧（平台配置，代码之外）

1. **主体与类目**：小程序需企业主体，并按平台当前规则选择与「录音质检/工具」相符的服务类目与资质（以提审时平台规则为准，不要照抄旧经验）。
2. **服务器域名白名单**（微信公众平台 → 开发设置）：
   - `request` 合法域名：**API 域名 + OSS 域名**。
     > 关键：小程序上传走 `uni.request` 发原始字节做预签名 PUT（不是 `uni.uploadFile`/multipart），
     > 所以 OSS 域名必须落在 **request** 白名单里，配到 uploadFile 里不生效。
   - `downloadFile` 合法域名：OSS 域名（导出下载、原件播放短链）。
   - `uploadFile`：本项目不用 multipart，可不配（配了也无害）。
3. **隐私保护指引**：涉及录音/相册/文件读取等接口，需在小程序后台按当前规则完成用户隐私保护指引配置与声明。
4. **订阅/客服等**：如启用额外能力另行配置（本项目未用到推送，不配）。
5. **小程序体验版 → 提审 → 发布**：先用体验版在真机跑完整闭环（登录→上传→退出重进→报告→导出→删除），
   验收通过再提审。真机验收清单见 `docs/S09-小程序闭环记录.md`。
6. **`urlCheck`**：提审前把 `manifest.json` 的 `mp-weixin.setting.urlCheck` 改回 `true`（见 §3.3 C4）。

## 8. 上线执行顺序（建议窗口）

1. **停写**：确认旧进程已退出、无 8080 监听、业务库无其他连接；确认无旧工作者在跑。
2. **备份**：完整备份 + `SHA256SUMS` + 抽样恢复验证（失败即停）。
3. **建目标库**：把第 2 步的 dump **直接导入**目标库（等价于自带 22 张表与 10 行迁移台账），
   核对表数 22、`schema_migrations` 10 行版本唯一。**无需跑 V2–V11 脚本，也无需重跑迁移。**
4. **裁决历史作业**：`export_jobs` 4 行 FAILED 的处理方式落纸（见 §12）。
5. **改配置**（§3.3 C1/C3 + `manifest.json` C4），构建三端产物。
6. **下发密钥**：新库密码 + 新 JWT 密钥 + 云凭据 + 回调令牌（安全渠道）。
7. **起后端**：确认启动日志无 `NOT_CONFIGURED` 告警（OSS/听悟/OCR/字体四类告警都不应出现）。
8. **发布前端**：后台 `dist` 上静态目录；小程序上传体验版；H5 上静态托管。
9. **配置回调**：听悟管控台填入 `https://<域名>/api/callback/tingwu/<令牌>`。
10. **冒烟验收**（§9）→ **真机闭环**（§9.3）→ 通过后才对外发布。

## 9. 上线后冒烟与验收

### 9.1 进程与配置（5 分钟）

| 检查 | 期望 |
|---|---|
| `GET https://<域名>/api/agreements` | HTTP 200，无认证 |

| 后台首页刷新子路由（例：/accounts） | 200（SPA 回退生效） |

### 9.2 关键链路（后台，ADMIN 账号）

1. 初始管理员能登录，改动密码后旧密码失效。
2. 三角色越权实测：OPERATOR / INVESTOR 访问 ADMIN 专属端点应 403（含规则修改、账号管理、审计明细）。
3. 规则批量导入预检 → 提交 → 生效；`POST /api/admin/recordings/{id}/reanalyze` 能追加新版本且旧版本可回读。

5. 审计页能看到上述动作的审计行。

### 9.3 真机闭环（微信）

登录 → 上传（录音 / 图片二选一）→ 退出重进仍可见 → 处理中进度 → 报告（问题 / 对话两个 Tab）→
「保存记录」与「含原件打包」下载 → 删除 → 记录消失且原件停止签发。
覆盖至少一条**真实双人催收通话**，并确认说话人聚类结果与规则命中可解释（`scripts/make-cuishou-samples.sh` 可生成音色样本用于对比）。

- OSS：bucket 为**私有**，对象前缀受限，生命周期策略与 30 天保留一致；确认无匿名可读。

## 10. 回滚方案

| 层级 | 回滚动作 |
|---|---|
| 后端代码 | 保留上一版 jar，`SIGTERM` 停止新进程 → 用旧 jar + 同一套环境变量重启 |
| 前端 | 静态目录切回上一版 `dist`（保留上一版目录，勿覆盖） |
| 小程序 | 后台「版本回退」到上一已发布版本（体验版可直接换回旧产物） |
| 数据库 | **脚本不提供自动反向 DROP**。按 `docs/quality-migration-runbook.md`：停写 → 用当期备份恢复到隔离库核对 → 人工制定补救 → 授权后执行。禁止盲目 `DROP` |
| 云端 | 已提交的听悟任务与已上传对象**不能靠回滚撤销**；确认受理的按实际账单处置，不确定的保留 `RESERVED` 并升级 |

回滚判据（任一命中即回滚）：登录全线失败、上传 100% 失败、报告生成停滞、导出全失败、
出现越权读取他人数据、云侧异常计费。

## 11. 上线后 24 小时观察

- **队列**：`recognition_tasks` 不应长期停在 `QUEUED/TRANSCRIBING/PARSING`；看后台总览「当前队列」。
- **失败率**：失败量/失败原因（`error_code`）分布；`SUBMIT_UNCERTAIN` / `SUBMIT_UNRECONCILED` / `QUOTA_UNSETTLED` 出现即人工介入（只读候选队列 `GET /api/admin/ops/reconciliation`），**不自动退款、不自动重提**。
- **租约与重试**：确认没有作业无限重试；`attempt_count` 增长应受 `max-attempts` 约束。
- **保留期作业**：30 天清理按计划推进，`deletion_jobs` 无长期滞留；对象是否真被删除需抽查 OSS。
- **审计**：登录、上传、导出、删除、规则修改均有审计行且不含敏感原文。
- **告警通道**：当前 ERROR 只写日志，**尚未接入外部告警**。上线前请确认值守方式（人工巡检或后续接告警通道）。

## 12. 待业务决策的门禁（不确认不上线）

这些是产品/合规口径，不能用默认值冒充已批准：

1. **PDF 脱敏口径**：是否两端（C 端与后台）一致；地址按「省市保留、路名门牌涂掉」的路号级口径需验收。
   注意：PDF 脱敏**不代表**原始音频已匿名。
2. **保留期**：原件 30 天已定；**文本/报告/审计保留时长未定**（不能按原件 30 天推断）。
3. **账号删除口径**：匿名化还是删行；抹除后财务核对不得恢复个人业务数据。
4. **云端结果删除能力**：听悟结果与 OSS 对象的删除/保留条款，上线前向云侧核实。
5. **历史遗留 `export_jobs` 4 行 FAILED** 的处置决定。
6. **无真值准确率**：没有标注真值，不得拿 confidence 或成功率冒充准确率（对外不可这么写）。

## 13. 已知坑位速查（本项目真实踩过的）

| 坑 | 症状 | 处理 |
|---|---|---|
| bucket 名含点号 | 上传签名 500 / 预签名异常 | 换成合法 bucket 名（不能有点号） |
| `DITING_OSS_ENDPOINT` 未显式 https | 预签名地址协议不对 | 写成 `https://oss-cn-<region>.aliyuncs.com` |
| 环境变量映射缺失 | 配了变量但后端仍读占位值 | 对照 §3 确认 `application.yml` 里有 `${...}` 映射 |
| `VITE_BASE_URL` 带路径 | 小程序构建直接报错 | 小程序仅允许源站，去掉路径 |
| 假 appid 提审 | 真机请求被拒 | 用 `wx`+16 位十六进制真实 appid 构建 |
| 跨域部署未改 CORS | 后台报 `Invalid CORS request` 403 | 优先同源部署；否则按域名收敛白名单 |
| 刷新后台子路由 404 | history 路由无回退 | 反代加 `try_files … /index.html` |
| 用 `--force` 跑迁移 | 部分成功后被掩盖 | 错误即停，逐版本核验 |
| 旧 jar + 新 Bucket（2025-09 后创建） | 上传 403 `AccessDenied / V1 signature is forbidden`（EC `0002-00000080`） | OSS 已对新 Bucket 禁用 V1 签名；**必须用 2026-09-27 21:30 之后构建的 jar**（预签名已切 V4 + 自动推导 region）；自查：`/api/upload/sign` 返回的 URL 应含 `x-oss-signature-version=OSS4-HMAC-SHA256` |
| `mysql -D testdb < schema.sql` | 数据写进真实库 | 剥掉 `CREATE DATABASE` / `USE` |
| 本地 `DITING_JWT_SECRET` 太短 | `mvn test` 大量 error，非代码问题 | 换 ≥32 字节密钥（或测试时 `env -u`） |
| 导出字体缺失 | 导出固定 503 | 配好有授权的中文字体文件路径 |
