# S09 小程序完整闭环 · 记录

版本：v1.0 · 日期：2026-09-24 · 阶段：S09
规格依据：[开发文档](./开发文档.md) §4.1 小程序页面规格、§5.2 状态机、§7.2 C 端接口；[开发计划](./开发计划.md) §12 S09。

**结论摘要**：小程序按新契约走通「额度预检 → 同意 → 选文件 → 原始字节上传 → 校验 → 登记 → 进度 → 报告 → 历史 → 删除」；
轮询、分页、幂等键、错误文案都抽成**可单测的纯逻辑**；服务端补上分页列表、墓碑删除与抹除作业。
验证：**171 项单元/切片测试** + **26 项服务端端到端断言** + **小程序逻辑 5 组断言**全部通过。
真机（微信开发者工具与授权真机）未测，按「离线通过」计。

## 1. 服务端补齐的闭环接口

| 方法/路径 | 变化 |
|---|---|
| `GET /api/task/list` | 改为分页：`page`（从 1 起）/`pageSize`/`status`，返回 `{items,total,page,pageSize}`；**已删除记录不再出现** |
| `DELETE /api/task/{id}` | 写墓碑（`deleted_at` + `DELETING`）→ **立即不可读** → 幂等登记 `deletion_jobs`，返回 `{deletionJobId,status}` |
| `DELETE /api/privacy/erase` | 本人全部记录写墓碑 → 登记一个 `ERASE` 作业（同一用户只有一个） |
| `GET /api/deletions/{jobId}` | 清理状态：只返回本人作业与状态/计数，**不含原文与对象 key** |
| `POST /api/task/submit` | 支持客户端幂等键（小程序每次提交动作生成一个，重试沿用） |

删除语义明确了边界：**可见性撤销与外部清理分开**。本轮做到「立即不可读 + 登记清理作业」，
OSS 对象与导出产物的真实清理属 S13，所以前端提示语是「已删除，正在清理原件」而不是「已彻底删除」。

## 2. 小程序改动

| 文件 | 作用 |
|---|---|
| `utils/polling.ts` | 轮询控制器：同一页面只有一个定时器、重复 `start` 不叠加、终态自动停止、`stop` 后不再触发 |
| `utils/paging.ts` | 分页合并：按 id 去重、保持服务端顺序，弱网重试不会出现重复项 |
| `utils/idempotency.ts` | 一次提交动作生成一个幂等键，重试沿用同一个 |
| `utils/errors.ts` | 按 `symbol` 翻译成人话（额度用完/过期/未配置/状态冲突…），并区分是否值得重试 |
| `pages/upload` | 提交前查额度并拦下 0 份的情况；提交带幂等键；失败用服务端文案 |
| `pages/progress` | 用轮询控制器；`WAITING_ROLE` 时给出「确认角色并看记录」入口；网络抖动只在连续失败时提示一次，不无限重试 |
| `pages/history` | 分页 + 「看更早的记录」；长按删除（二次确认 → 立即从列表移除 → 提示清理状态）；按状态分流到进度页或报告页 |
| `pages/privacy` | 抹除后展示真实清理状态（含待清理项数）；补充「原件保留 30 天」「删除后立即不可读」两条说明 |
| `pages/about` | 新增两个 FAQ：**保留多久**（原件 30 天、删除后立即不可读、已下载副本无法回收）、**判读怎么来的**（按已启用规则、角色未确认不下角色结论、不是法律意见） |

## 3. 测试与证据

| 层 | 用例 | 结果 |
|---|---|---|
| 单元 | 服务端 171 项（S09 新增墓碑读取用例） | 通过 |
| 端到端 | 独立库 `diting_s09_test` + 8088 实例：分页/筛选/额度/删除/抹除/归属 | **26 项通过** |
| 小程序逻辑 | `fe-app-logic-harness.mjs`：APP-02 轮询不叠加且终态停止、APP-03 幂等键、APP-06 分页去重、APP-08 额度文案、状态分流 | 5 组断言通过 |

**E2E 抓到的两个真实缺陷（已修）**：

1. **重复路由**：新的分页 `GET /api/task/list` 加上后，旧的数组版方法没删，Spring 启动直接失败
   （`Ambiguous mapping`）。这是编译期看不出来、只有跑起来才暴露的问题。
2. **墓碑没有覆盖读取路径**：删除后 `GET /api/report/{id}` 仍返回 200——`requireOwned` 只校验了归属，
   没有校验 `deleted_at`。已改为「墓碑优先」，并补了单测；这也是开发文档「先拒绝读，清理异步」的硬要求。

证据文件（`docs/evidence/S09/`）：`java-tests-*.log`、`e2e-closure-*.log`、`fe-app-logic-harness.mjs`。
复现方式见 `diting-server/src/test/resources/app/README.md`。
