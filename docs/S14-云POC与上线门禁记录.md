## 1. 已完成的官方契约核对（核验日期：2026-09-24）

来源（均为阿里云官方文档，未引用任何未经确认的价格）：

- CreateTask API：<https://api.aliyun.com/document/tingwu/2023-09-30/CreateTask>
- 听悟开发者指南（离线转写）与 API 调试页：<https://next.api.aliyun.com/api/tingwu/2023-09-30>
- 离线转写使用须知（格式/大小/时长/采样率）：阿里云帮助中心「听悟 · 离线转写」

### 1.1 与现有实现一致的部分（确认无需改动）

| 项 | 官方契约 | 我们的实现 |
|---|---|---|
| 请求 | `PUT /openapi/tingwu/v2/tasks?type=offline`，Version `2023-09-30`，Domain `tingwu.cn-beijing.aliyuncs.com` | 一致 |
| 转写参数位置 | `Parameters.Transcription`（不是顶层 Transcription） | 一致（S05 已修正） |
| 说话人分离 | `Transcription.DiarizationEnabled` + `Diarization.SpeakerCount` | 一致；默认不指定人数（0 表示不定） |
| 响应层级 | `{RequestId, Code, Message, Data{TaskId, TaskKey, TaskStatus}}` | 一致（读 `Data.TaskId` / `Data.TaskStatus`） |
| 结果地址 | `Data.Result.Transcription`（完成时才有） | 一致；未完成不解引用 |
| 远端状态 | 示例含 `ONGOING`、`COMPLETED` | 映射表覆盖 QUEUEING/ONGOING/COMPLETED/FAILED 等 |
| 流控 | CreateTask 请求速率 20/秒 | 我们的管线是秒级串行，远低于限制 |

### 1.2 核对中发现并已修正的三处不匹配

| # | 问题 | 官方契约 | 修正 |
|---|---|---|---|
| 1 | **源语言取值错误** | `Input.SourceLanguage` 的取值是 **`cn`**（另有 en/yue/ja/fspk、auto、multilingual），**不是 `zh`** | 改为可配置 `diting.aliyun.tingwu.source-language`，默认 `cn`；测试断言请求体含 `"SourceLanguage": "cn"` |
| 2 | **结果链接可能是 http** | 官方示例里 `Result.Transcription` 出现过 `http://…aliyuncs.com/…`；而我们的策略强制 HTTPS，会把正常结果一律拒掉 | 新增 `allow-http-result`（默认开）与 `http-result-host-suffixes`（默认 `aliyuncs.com`）：**只对受信任云存储域名**放开 http，其它域名仍必须 HTTPS，且私网/回环/链路本地地址一律拒绝（防 SSRF 的保护不变） |
| 3 | **业务对账缺少关联键** | `Input.TaskKey` 是官方定义的「用户自行设置的自定义标识」 | 提交时把任务的幂等键写入 `Input.TaskKey`，供提交结果不确定时排查与对账 |

### 1.3 核对到的真实边界（用于收紧或核对产品策略）

| 项 | 官方限制 | 我们的现状 |
|---|---|---|
| 支持格式（音频） | 单/双轨 mp3、wav、m4a、wma、aac、ogg、amr、flac、aiff（另有多种视频格式） | 允许列表是 m4a/mp3/wav/amr/aac/flac —— **是官方集合的子集**，安全 |
| 文件大小 | ≤ **6GB** | 我们限制 50MB（更严），待真机确认是否放宽 |
| 音频时长 | ≤ **6 小时** | 产品策略默认 10 分钟（`max_recording_minutes`），更严 |
| 采样率 | 8K/16K/24K/48K | 未限制（由听悟处理），需在多说话人样本里覆盖 8K/16K |
| 提交地址 | 必须公网可访问，**URL 只能用域名、不能用 IP、不可含空格、尽量避免中文** | OSS 预签名走 `oss-cn-*.aliyuncs.com` 域名 ✓ 符合 |

## 4. 上线前待办（按优先级）

1. **凭据与域名**：OSS 私有 bucket + 服务端凭据 + CORS/PUT、听悟 AppKey 与配额、微信 appid/secret + 合法 HTTPS 域名。
   **（2026-09-24 已改）** `application.yml` 的库密码与 JWT secret 已改为环境注入，文件里不再有真实值：
   启动前必须 `export DITING_DB_PASSWORD='<库密码>' DITING_JWT_SECRET='<强密钥>'`（或用
   `--spring.datasource.password=` / `--diting.jwt.secret=` 传参），缺失时应用**启动即失败**（不再有默认值兜底）。
   单元测试自带测试值（`src/test/resources/application.properties`），不需要真实凭据。
   因旧值曾出现在配置文件与本地终端里，**上线前必须轮换这两项**。
2. **字体授权**：把 `diting.export.font-path` 指向持有合法授权的中文字体（如思源黑体 OFL），并做一次中文渲染回归。
3. **策略口径**：PDF 脱敏是否两端一致、文本/报告/审计保留时长、账号删除是匿名化还是删行、云端任务结果删除能力。
4. **执行 S14 第 2—6 步**并回填结果；任何关键项未通过不得上线。
