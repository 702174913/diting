# 谛听开发文档

版本：v1.0 · 日期：2026-09-24 · 状态：开发规格，尚未完成云端联调。

配套文件：[开发计划](./开发计划.md)。本文定义“做什么、按什么契约做”；开发计划定义“先后顺序、测试与验收”。本文不是已实现功能声明。

## 1. 目标、范围和可行性

以当前工作区 diting-app、diting-admin、diting-server 为实现主体，保留谛听界面风格，构建“上传录音→转写→确认说话人→规则质检→报告→导出”的闭环。后台新增录音资产、规则库、策略设置，补齐真实账号权限与审计。

技术路线：阿里云 OSS 预签名直传 + 通义听悟离线转写；服务端自建规则判读、报告与导出。转写和声学说话人聚类不等于违规识别，更不自动等于“催收员/客户”身份识别。目标功能可实现，但凭据未齐、真实云调用与微信真机验证尚未完成，不能承诺当前已经可用或具体识别准确率。

不做：大模型判读、独立模型管理、付费订阅、渠道归因、应用内录音、旧项目代码合并。没有来源的经营指标保留演示或待采集标记，不造数。

## 5. 架构与处理流程

```text
用户登录 → 同意/预检 → upload_sessions → OSS原始字节PUT
 → complete校验对象/真实媒体参数 → 预占额度+登记任务
 → MySQL持久作业 → 听悟CreateTask → 服务端查询/回调唤醒
 → 下载可信结果 → 解析时间序列 → 角色确认 → 规则判读
 → 事务发布report_versions → 小程序/后台报告
 → export_jobs → PDF或PDF+音频ZIP → 短时授权下载
```

### 5.1 上传契约

对象key服务端生成，不包含用户可控制路径；绑定owner。提交携带uploadId，服务端取可信objectKey。验证对象存在、长度、真实格式/时长，不能信任扩展名和客户端durationSec。未使用上传对象按TTL清理。

预签名返回method、必需headers、expiresAt；客户端严格一致。微信使用文件读取与支持PUT的请求发送原始二进制，H5发送原始File；禁止multipart POST。微信大文件内存和超时必须先测，最大大小/格式列表由POC确定并服务端配置。无法测出真实上传百分比时显示上传状态，不虚构进度；不因限制擅自改成后端中转。

### 5.2 状态机

统一枚举：`UPLOADED → QUEUED → SUBMITTING → TRANSCRIBING → PARSING → WAITING_ROLE → ANALYZING → COMPLETED`；失败分支FAILED；无有效语音INVALID；删除DELETING/DELETED优先。

UPLOADED表示已验证上传，QUEUE登记/额度事务成功后进入QUEUED。上传会话阶段与任务阶段分开存储，不把未验证对象当可提交任务。无需角色规则或角色已确认可跳过WAITING_ROLE。旧PENDING/ONGOING仅按迁移规则转换，不前后端各用一套。

| 状态 | 允许动作 | 退出条件 |
|---|---|---|
| QUEUED | 后台领取 | 租约和版本CAS成功 |
| SUBMITTING | 调用/对账 | 获取可信remote_task_id；不确定结果保留对账状态 |
| TRANSCRIBING | 定时查询 | 远端完成/失败 |
| PARSING | 获取、验证、持久化句子 | 解析成功并满足时间字段要求 |
| WAITING_ROLE | 用户/操作员确认 | 映射版本通过校验 |
| ANALYZING | 规则判读 | 句子、命中、报告完整事务提交 |
| COMPLETED | 读取/导出/创建重算版本 | 不回退；重算另建分析版本 |
| FAILED/INVALID | 看安全错误与允许的恢复操作 | 不盲目创建新云任务 |
| DELETING/DELETED | 清理/最小墓碑 | 禁止获取、导出、角色修改、回调发布 |

### 5.3 并发与恢复

MySQL作业使用version、lease_until、next_attempt_at、attempt_count领取和重试；用户离页不停止处理。回调、轮询、重启并发仅允许一个处理者发布。同一报告版本唯一键保证结果幂等。

CreateTask超时可能云端已接受，按业务关联键对账；未核实远端幂等机制前禁止自动盲重试。云端成功但结果下载/DB写入失败，只重试结果阶段。回调仅唤醒已关联任务，按实际官方机制校验并服务端主动查询，不信任请求内任意结果URL。

听悟回调的实际机制（2026-09-27 核对官方帮助文档，见 §7.3）：**回调地址在听悟管控台按项目配置**（回调方式=HTTP post），CreateTask 仅传 `Input.ProgressiveCallbacksEnabled=true`，没有 URL 参数；回调体为 `{"Code":"0","Data":{"TaskId","TaskStatus":"ONGOING|COMPLETED|FAILED","TaskKey","Result"}}`（TaskId 在 `Data` 下）；管控台保存地址时先发一条 `Data.Test` 连通性检查；接收方必须 **5 秒内返回 HTTP 200**；官方文档**未提供**回调验签字段，因此来源约束用「路径共享令牌 + 任务归属校验」，不用自造签名头。

结果下载仅允许可信HTTPS来源，校验重定向、拒绝内网地址、限定体积/超时；敏感文本、签名URL、云密钥禁止进日志。异常摘要供用户显示，内部诊断使用requestId与安全错误码。

删除先写墓碑/拒绝访问，再做外部清理；所有工作者发布前再次检查墓碑，失败保留可恢复清理任务，避免迟到回调恢复数据。

## 7. API契约

### 7.1 公共约定

沿用`R{code,message,data}`，成功code=0。失败HTTP语义与业务symbolic code由错误枚举映射保持一致：401未登录、403无权限、404资源不存在/归属不符、409版本冲突、422格式/参数不合法、429额度或限流、503未配置/服务不可用。客户端拦截器必须同时处理HTTP失败与信封失败；业务枚举至少包含QUOTA_EXCEEDED、ROLE_UNCONFIRMED、AUDIO_EXPIRED、PROCESSING、FAILED、NOT_CONFIGURED。

分页`{items,total,page,pageSize}`，page从1开始、默认20、上限100。时间为ISO8601含时区；毫秒与秒字段不得混用。身份由token解析，不接受body内userId冒充调用者。

LoginResult统一`{token,userInfo:{id,username,nickname,hasPassword,hasWechat},isNewUser}`。后台登录返回`{token,role,nickname}`，不可与C端token互用。

## 8. 规则语义、计分和版本

规则类型（**目标角色功能当前隐藏**，见下）：
1. hit：任意一段语句包含任一关键词即命中；精确规范化匹配，不本期暗加模糊/LLM判断。
2. require：任意一段语句命中触发词后，后续N条发言内应包含任一应答词。按发言条数计窗口。缺失时保存触发证据，不假造应答原句。
3. must-have：完整通话未出现必需词，记录通话级缺失，sentenceId可空。

**目标角色（暂隐藏，2026-09-27）**：角色未确认时（当前恒为未确认，因为角色确认没有 HTTP 入口）
角色范围与触发角色一律按「任意角色」处理，不区分说话人——若保留原口径，会让
role_scope=AGENT/CUSTOMER 的规则静默失效。角色已确认时角色限定照旧生效。开关：服务端 `RuleMatchService.ROLE_TARGETING_HIDDEN`、
后台 `lib/features.ts::ROLE_TARGETING_ENABLED`；两处一起改回即可恢复原来的角色限定判读（含未确认角色时跳过并在 skipped 说明）。

规范化：全半角、空白/标点及英文大小写处理，保留原文偏移映射；输出ranges，不返回可执行HTML。每个测试必须覆盖位置映射而不只判断布尔命中。

分数建议口径：同规则/同证据去重，初版每规则每通话最多扣一次，保留全部证据。该去重扣分策略仍需业务确认。`riskScore=min(100,去重扣分总和)`；`complianceScore=100-riskScore`；`riskScore>=threshold`标风险。默认阈值60，边界测试59/60/61。具体命中仍展示，不因未达到整通话阈值而隐藏。

默认每日3份、最大10分钟仅可编辑初值；0份表示无免费可提交额度，不是无限。消费/预占原子执行；建议只退还确定未被云接受的失败任务，不确定提交先对账，退款规则上线前明确。

角色未知显示说话人A/B/未知；不得将SpeakerId=0视为催收员。目标角色功能隐藏期间不等待人工确认，规则一律按任意角色判读；恢复后：存在角色规则时等待人工确认；多于两人允许UNKNOWN，不强行二人映射。修改角色创建新分析与报告版本，用expectedRevision防覆盖；失败不破坏旧报告。

报告引用平台规则；V13 起可附带后台为规则绑定的法律条款作为「相关依据」（原文以现行有效版本为准，不构成法律意见），不冒称法条。A/B/C/D断点未批准，不擅自上线；无命中文案为“未命中本次启用的规则”，不写“完全合规”。

| 角色确认 | 仅本人 | 是 | 是 | 否 |
| 原音频/含音频ZIP | 本人且未过期 | 授权且未过期 | 否 | 否 |
| 修改规则/策略/账号 | 否 | 是 | 否 | 否 |
| 法律条款读／写 | 否 | 是／是 | 是／否 | 否 |
| 删除 | 本人 | 授权范围 | 否 | 否 |
| 审计明细 | 否 | 是 | 否 | 否 |

JWT含身份域/受众；用户与后台相同数字ID不可互相冒充。每次请求查角色和启用状态，不能只信前端切换视图。

原件从上传时间保留30天；到期即停止新授权，清理原件及所有含音频ZIP、孤立上传。文本/报告保留时长待确认，不默认为永久。全部删除先撤销可见性，再异步删句子/报告/命中/导出和OSS；审计只留必要元数据。云端任务结果的删除能力与保留条款上线前核实，披露已下载副本不可撤销。

PDF方案：固定服务端HTML模板→PDF，禁止任意外部资源，字体需合法中文资源。PDF显示报告版本、时间、平台规则依据、逐句及命中；ZIP为PDF+未改动原始音频。文件名建议`DT-年份-任务号-v版本.pdf/.zip`，不得含用户敏感姓名。

PDF脱敏建议两端一致，但仍待最终确认；姓名/电话/身份证/工号/地址的识别与漏脱敏样本需要验收（地址按路号级口径：省市保留、路名门牌涂掉，见 RedactionService）。PDF脱敏不代表原始音频已匿名。对OPERATOR接口必须脱敏，不能仅靠前端遮罩。脱敏后重新计算显示文本ranges，避免原文偏移错位或泄露。

导出是有owner/版本的异步作业；无违规项的报告，同用户同版本同选项可复用未过期产物，不跨权限共用。有违规项的报告每次重新生成 PDF/ZIP：法律条款原文及绑定实时生效，并未冻结在报告版本中，即使当前未绑定也可能随后新增绑定，不能仅凭报告版本复用旧产物。下载链接短TTL建议15分钟，含音频ZIP有效期不得超过原件截止时间；确切产物TTL上线前配置。删除与导出并发时发布前复查墓碑并销毁产物。不能瞬时撤销已经签发或已下载的所有副本，对风险边界诚实说明。

下载必须带**另存为处置头**：预签名 URL 里下发 `response-content-disposition=attachment; filename="DT-年份-任务号-v版本.pdf|.zip"`（处置头是签名参数，不能事后拼 URL）。不带它时 PDF 会被浏览器内联打开，用户拿不到文件。后台（diting-admin）在作业完成时由前端自动另存（可在「导出任务」里关掉或手动重签）；C 端仍由用户显式触发下载。

C 端 H5 把预签名 URL 直接交给浏览器另存，**不自读响应头**：OSS 未通过 CORS 暴露 `content-disposition`，而 `uni.downloadFile` 在 H5 里会 `getResponseHeader('content-disposition')` 取文件名 —— 浏览器报 `Refused to get unsafe header`，文件名也一起丢掉（退化成 OSS 对象名）。小程序端仍用 `uni.downloadFile` 取临时文件后转发/保存，文件名由前端按同一口径拼（`utils/exportArtifact.ts`）。

## 10. 指标口径

业务时间Asia/Shanghai，查询采用半开区间[start,end)。各指标返回source/period/sampleSize或必要分母；零分母比例返回null并显示暂无数据，不伪造100%。

| 指标 | 来源与去重 | 计算/边界 |
|---|---|---|
| 提交任务量 | recognition_tasks.created_at | 按task去重，重复提交不增加 |
| 有效报告量 | report_versions首个published_at | 按task去重，角色重算不重复算新报告 |
| 当前队列 | 当前QUEUED及处理阶段 | 时点库存，不混作期间处理量 |
| 完成/失败量 | 对应完成/失败时间及task | INVALID单列；定义是否最终失败 |
| 失败率 | 期间终态失败/(成功+失败+INVALID) | 明示分母，不与ASR准确率混淆 |
| 耗时 | 各阶段时间差 | 样本量、均值/P95；缺时间不补0 |
| 上传率 | upload_sessions / users | 分母=区间新增注册用户数，零分母返 null |
| 角色确认覆盖率 | audit_log（SPEAKER_MAP_CONFIRM） | 分母=完成量；只证明有人确认过角色，不代表判读正确 |
| 用户转化漏斗 | users + upload_sessions + recognition_tasks + report_versions + export_jobs | 全部按用户去重，逐环是上一步子集；付费环节无数据源不展示 |
| 按日序列（有效报告/新增注册） | 首版 published_at、users.created_at | 窗口内逐日补零，缺数据的天是0 而不是消失 |

已下线的分组（不再在这里定义口径）：违规图谱、合规风控、质检运营时段/额度、增长与分层、质量与规则版本时效、财务。它们对应的聚合 SQL 已从 `StatsMapper` 删除；要恢复须重新定义口径并补回索引与测试。

删除数据后的历史聚合保留口径待政策明确；初版查询现存非删除业务记录并标注范围，不凭空补历史。MRR/ARR、渠道、准确率、误报漏报率、综合健康分无数据源不接真。confidence既不等于准确率也不等于完整度。

## 11. 配置与运行准备

所有密钥仅服务端环境注入，文档不含任何真实值。

| 配置组 | 必需项 | 验证 |
|---|---|---|
| 数据库 | 地址/库/账户/密码、时区、迁移权限 | 备份可恢复、最小权限；禁止默认删库；启动自检核对迁移台账与关键对象，缺迁移即拒绝启动（`DITING_STARTUP_SCHEMA_CHECK`） |
| JWT | 强签名secret、有效期、身份域/受众 | 两端隔离、失效策略 |
| 微信 | appid/secret、合法request/upload/download域名 | 真机HTTPS、凭据不入前端 |
| OSS | endpoint/bucket、服务端凭据、CORS/PUT、TTL | 私有bucket、受限object前缀、生命周期 |
| 听悟 | endpoint/AppKey、服务端凭据、配额/回调 | 实际API结构/限额/授权确认 |
| 作业 | 租约、退避、并发、重试上限 | 防重复、崩溃恢复与告警 |
| 媒体 | 允许格式/大小、真实时长检测 | POC决定支持边界，失败关闭 |
| PDF/ZIP | 固定模板、字体、并发/大小、产物TTL | 中文、长文、资源隔离 |
| 隐私 | 原件30天、文本期限、审计期限 | 后两者上线前确认；副本一并治理 |

生产缺配置应NOT_CONFIGURED，不返回模拟报告。测试profile才允许mock。阿里云价格/限额/回调协议属于上线前官方核验项，本文不宣称已核验最新值。

## 12. 测试门禁与待决策

测试分三层：离线契约与单类单元测试、真实云POC、微信真机闭环。仅第一层通过不能称项目已完成。逐阶段用例与验收见[开发计划](./开发计划.md)。禁止全量ts:check/lint:eslint/build:local/测试；文档落地不运行项目构建。

上线前仍需确认：PDF脱敏最终口径、文本/报告/审计保留时长、A/B/C/D等级、同规则扣分与额度失败退还策略、微信可支持文件大小、云端幂等与结果删除能力。各项在开发计划设置阻塞门禁，不能用默认值冒充用户已批准。
